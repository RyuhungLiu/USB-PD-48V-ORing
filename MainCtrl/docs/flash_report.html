Further possible savings

  1. X035 64-bit division 1,190 B (10.2% of X035 used): sys_time_ms() and sys_time_us() divide the 64-bit SysTick by 48000/48, which links in libgcc's __udivdi3 (934 B) and its lookup table __clz_tab (256 B). Shifting right first and then doing a 32-bit division, or using multiply-and-shift, would remove all of it. The X035 still has plenty of space, so this is not urgent.
  2. V203 string constants 3,920 B: mainly on-screen hint sentences, menu descriptions and non-LOG format strings (the longest about 40 characters). Shortening the twenty or thirty longest could save a few hundred bytes, at the cost of less descriptive text.
  3. V203 prot_log has 136 B of initial values in .data: only so that it carries the magic "PEVT" from boot. Moving it to .bss and writing the magic during initialization would save about 128 B of Flash.
  4. switch lookup tables (CSWTCH) 196 B: the compiler turns string switches into lookup tables; this is a normal optimization and handling it manually is not recommended.
  5. main 9,272 B needs no action: this is the result of LTO inlining each module's *_init/*_process into it; the source-file attribution has already been split back to the individual files in the "By module" table.

Method

  • Sizes come from the ELF of the actual build: the load image of .init + .vector + .text + .data, which equals the .bin size (V203 52,784 B, X035 11,676 B).
  • Source-file attribution comes from a build of the same program with -g2 added, reading only the DWARF line table and variable information. The V203 -g2 build is byte-for-byte identical to the release .bin; on the X035 two functions (main, USBPD_IRQHandler) each differ by 4 B, so X035 function sizes are always taken from the release build and then distributed to source files in proportion to the line numbers of the -g2 build.
  • Inlined code is attributed to its original source file via the line table; newlib/libgcc functions without debug information are attributed via the link map to the .a member they belong to.
  • Bytes without a symbol: null-terminated printable ASCII sequences are counted as string constants; of the rest, zero bytes are counted as alignment padding and non-zero bytes as anonymous constants (literal pools, jump tables, etc.).
  • The V203 program area of 57,344 B is limited by board_upload.maximum_size, with the last 8KB being the settings area; the X035 linker script sets Flash to 61KB, with the last 1KB being the NV page.
